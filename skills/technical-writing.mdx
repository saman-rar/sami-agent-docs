The technical writing skill helps you produce clear, accurate, task-focused documentation. Whether you need a new guide written from scratch, an existing page tightened up, or a review that catches unclear or outdated content, Sami applies a structured approach that keeps the reader's task at the center. Every claim is checked against source code, CLI output, or authoritative project references — nothing is invented to fill space.

## What this skill covers

- **New documentation pages** — writing Getting Started guides, API references, how-to pages, and conceptual overviews
- **Editing existing content** — improving clarity, reducing length, and fixing structure without losing meaning
- **Reviewing for accuracy** — checking whether documented behavior matches current source code and flagging mismatches
- **Auditing for outdated information** — identifying sections that describe removed flags, deprecated APIs, or changed defaults
- **Style and terminology guidance** — applying consistent naming, voice, and formatting conventions across your docs

## Example prompts

```
"Write a Getting Started guide for my API"
"Review this page and flag anything that's unclear or inaccurate"
"Make this section more concise without losing key information"
"Rewrite this paragraph in plain English"
```

## Writing principles Sami follows

Sami approaches documentation the same way a skilled technical writer would: lead each page with the outcome, address the reader as `you`, use imperative verbs for steps, and prefer active voice and present tense. Pages stay focused on one primary task rather than trying to cover everything at once. The happy path comes before alternatives and failure modes. Troubleshooting sections appear only where real failures cluster around a workflow.

Accuracy takes priority over polish. Sami verifies commands, flag names, API names, defaults, and examples against the current source before including them. If a claim cannot be verified, it is omitted rather than guessed at. Promotional language, rhetorical questions, and filler phrases are avoided — so is manufacturing examples or opinions to make prose sound more natural.

<Tip>
  Paste the relevant source code or existing docs into the conversation for the most accurate output. The more Sami can verify against real material, the less it has to infer — and the fewer corrections you'll need to make.
</Tip>
